# Alaska is a text formatter for web prose.

It applies typographic conventions to text: quotes, no-break spaces, dashes, arrows, symbols, and more.

The formatting engine `src/core.js` can be used in:

- [browser](#browser) via `browser/alaska.js` to format a page in the client, including text added later;
- [source](#vendored-core) via `src/core.js` to format strings in code, at render time;
- [CLI](#cli) via `cli/cli.js` to format static HTML files in place at build time.

## Notation

Formatted output contains invisible and lookalike characters. Examples write any non-ASCII character as `{U+XXXX}`, meaning one character with that codepoint. It is documentation notation, not input syntax.

| Notation   | Name                                            |
| ---------- | ----------------------------------------------- |
| `{U+00A0}` | NO-BREAK SPACE                                  |
| `{U+202F}` | NARROW NO-BREAK SPACE                           |
| `{U+2060}` | WORD JOINER (zero width, prevents a line break) |
| `{U+FE0E}` | VARIATION SELECTOR-15 (text presentation)       |

## Browser

Link `browser/alaska.js` in the head of a page:

```html
<html lang="en">
  <head>
    <script src="browser/alaska.js"></script>
  </head>
  <body class="alaska">
    <p lang="ru">Alaska applies Russian conventions to this element.</p>
    <p class="alaska-skip">Alaska does not format this element.</p>
    <div class="alaska-observe">Alaska formats nodes added to this element later.</div>
  </body>
</html>
```

`browser/alaska.js` is generated by `deno task build` from `src/core.js` and `src/dom.js`. It exposes no global and no JS API. Configuration is only through classes, `lang` and `data-*` attributes.

| Class            | Effect                                                                                                                                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `alaska`         | Text inside the element is formatted. Formatting is idempotent: formatting already-formatted text returns it unchanged. `test/fuzz.js` checks this on random strings under prose and math rules, in `en`, `ru` and no language. It is tested, not proven. Format at render time regardless. |
| `alaska-skip`    | The element and its subtree are not formatted.                                                                                                                                                                                                                                              |
| `alaska-observe` | A `MutationObserver` formats nodes added inside this element after load. It must be on or inside an `.alaska` element.                                                                                                                                                                      |

Always skipped inside `.alaska`: `code`, `pre`, `samp`, `kbd`, `script`, `style`. An `.alaska` element inside a skipped element (those, or `.alaska-skip`) is not a root and is not formatted.

Only the outermost `.alaska` is a root. A `.alaska` inside another `.alaska` is not formatted separately; it is traversed like any other element, and its own `lang` and `data-*` attributes apply to its subtree.

Observer scope: it watches `childList` on the subtree. Added or replaced nodes are formatted, including via `innerHTML` and `el.textContent = "..."`. In-place edits of an existing text node (`textNode.data`, `nodeValue`) are not observed, so text rewritten that way by a framework or script stays unformatted. An added node uses the `lang` and `data-*` attributes of its ancestors up to the outermost `.alaska`.

Inline elements do not break formatting within a block: `"Hello <b>x</b>"` pairs its quotes, and a minus sign or line-start dash looks at the text before the element. Block-level elements (`blockTags` in `src/core.js`) and `<br>` start a new line of context; `code`, `kbd`, `samp` and inline `.alaska-skip` elements count as a word. The observer sees only the added nodes, so it pairs quotes only in nodes added at the start of a block or in added block elements, and it does not format a minus sign or line-start dash at the start of any other added node.

## Vendored core

Use `src/core.js` into your code:

```js
import { commonRules, formatString, mathRules } from "./vendor/alaska/core.js";

formatString("5 meters", commonRules, "en"); // 5{U+00A0}meters
formatString("5 meters", { ...commonRules, placeNumberNbspWord: false }, "en"); // 5 meters
```

### `formatString(text, rules, lang, carry)`

| Param   | Type     | Notes                                                                 |
| ------- | -------- | --------------------------------------------------------------------- |
| `text`  | `string` | Input longer than 2,000,000 characters is returned unchanged.         |
| `rules` | `object` | Required. `undefined` throws a `TypeError`.                           |
| `lang`  | `string` | Language tag. See [Language](#language). May be `undefined`.          |
| `carry` | `object` | Optional. Shared across the pieces of one block. See [Carry](#carry). |

Returns the formatted string.

`commonRules` maps every rule name to its prose default: `true` for every rule except `placeArithmeticalSymbols`. `mathRules` is an overlay for [math zones](#math): `formatString("x - 5", { ...commonRules, ...mathRules }, "en")` gives `x {U+2212} 5`. A key missing from `rules` counts as off, so a partial object enables only the rules it lists:

```js
formatString("5 meters 50 %", { placeNumberNbspWord: true }, "en"); // 5{U+00A0}meters 50{U+202F}%
```

To disable one rule, spread `commonRules` and set it to `false`. To enable a subset, pass only those keys.

Call it on whole text blocks (a paragraph, a heading, a cell), not on fragments. Without a `carry`, quote pairing and neighbor-dependent rules see only the string you pass. See [Carry](#carry) and [Scope](#scope).

### Carry

Text split by inline elements (`"Hello <b>x</b>"`) reaches `formatString` in pieces. Pass the same `carry` object, a plain `{}`, to every piece of one block in document order, and quote pairing, the minus sign and the line-start dash read across the piece boundary. The object is opaque: only the core reads or writes it.

```js
import { commonRules, formatString, resetCarry } from "./vendor/alaska/core.js";

const carry = {};
formatString('"Hello', commonRules, "en", carry); // {U+2018}Hello
formatString(" x", commonRules, "en", carry); // {U+0020}x
formatString('"', commonRules, "en", carry); // {U+2019}
resetCarry(carry); // at every block boundary
```

Call `resetCarry` at the start and end of each block-level element. `blockTags` is the set of lowercase tag names the browser and CLI treat as blocks. Without `carry`, every call stands alone. Lookahead rules still see only the current piece (`5 <b>meters</b>`, `it'<b>s</b>`); see [Scope](#scope). The numeric range reads one token before its left number across the boundary (`x<b>86-64</b>` is left alone).

## CLI

Rewrites HTML files in place. Only text inside `.alaska` elements is changed. Files are written only if the output differs.

```sh
deno run -R -W cli/cli.js page.html docs/*.html --exclude 'docs/drafts/*'
```

- Arguments other than `--exclude` are file paths. The shell expands globs before the CLI sees them.
- `--exclude <pattern>` is repeatable. It is matched against each path exactly as given, so `./a.html` and `a.html` are different strings. `*` matches any characters including `/`, `?` matches one character, `[abc]` and `[!abc]` are character classes. Patterns are anchored to the whole path.
- Exit code is 1 if no files are given or any file fails.
- `lang`, `data-*` rule attributes, `alaska-skip`, and the skip elements behave as in the browser. `alaska-observe` has no effect.
- The parser is a streaming rewriter, not a full HTML parser. It handles void elements, optional end tags, `script`/`style` contents, and self-closing tags in `svg` and `math`. Character references (`&amp;`, `&nbsp;`) are passed through untouched and split the surrounding text into separate `formatString` calls that share one [carry](#carry): a reference that decodes to whitespace (`&nbsp;`, `&#32;`) counts as whitespace, any other as a word.
- The rewrite is in place, so the source files become formatted. Running it again changes nothing (formatting is idempotent, see [Output contract](#output-contract)).

A `%` or a currency sign after a number is a unit, so `placeNumberNbspWord` only joins a space the author already typed: a single regular space before it becomes `{U+202F}` (words get `{U+00A0}`). It never inserts a space and never moves the sign, so `50%` and `100{U+20AC}` stay as written. It declines when a number follows the sign (`10 % 3`, `5 %5`, `100 {U+20AC} 5`) or a word touches it (`5 %d`), because that is modulo or a format specifier. The rule is the same in every language: Russian writes `50 %`, `ja` and `ko` write `50%`, which stays as written.

Shortcodes (`\pm`, `\alpha`, `\dinkus`, `\shrug`, `\arrn`, `\square`) are gated by their own category rule. A shortcode is a backslash followed by ASCII letters of either case, and names are case-sensitive. Unknown shortcodes are left as written. A name directly followed by `{` is a LaTeX command with an argument and is left as written (`\sqrt{2}`). The shortcode sets are not final and may change; the tables in `src/core.js` (`mathShortcodes`, `greekShortcodes`, `ornamentShortcodes`, `emoticonShortcodes`, `arrowShortcodes`, `currencyShortcodes`, `shapeShortcodes`, and `shapeMathShortcodes`, which only overrides `\star` and `\diamond` in a math zone) are the source of truth. `\blacktriangleleft`, `\blacktriangleright`, `\blackheartsuit`, `\blackspadesuit`, `\blackclubsuit` and `\blackdiamondsuit` end with `{U+FE0E}` so platforms draw them as text, not colour emoji. `\doublecircle` gives U+25CE and `\fisheye` U+25C9. The suits `\heartsuit \spadesuit \clubsuit \diamondsuit` give the outlines U+2661, U+2664, U+2667 and U+2662, and `\blackheartsuit \blackspadesuit \blackclubsuit \blackdiamondsuit` the filled U+2665, U+2660, U+2663 and U+2666. The suit names are LaTeX's, but LaTeX draws `\spadesuit` and `\clubsuit` filled and these are outlined. `\blackdiamond` (U+25C6) and `\blackdiamondsuit` (U+2666) are different glyphs.

`\registered`, `\trademark` and `\phonogram` are deliberately short and are not LaTeX names (LaTeX has `\textregistered`, `\texttrademark` and `\textcircledP`). The ASCII forms `(c)`, `(tm)`, `(r)` and `(p)` are not converted: write `\copyright`, `\trademark`, `\registered` or `\phonogram`.

## Language

Language comes from the `lang` attribute of the nearest element (browser and CLI) or the `lang` argument (core). It inherits down the tree. In the browser, an empty `lang=""` inherits; in the CLI, an explicit `lang=""` resets to no language.

The primary subtag is the text before the first `-`, lowercased: `en`, `EN` and `en-US` all mean `en`. Tags with an underscore (`en_US`) and language names (`english`) are not recognized. For `en` the region also picks the quote style: the first two-letter alphabetic subtag after the primary one, looking no further than a one-letter subtag (`x`, `u`), is the region, and `US` and `CA` select double outer quotes. Every other region and no region select single outer quotes. `en-Latn-US` and `EN-us` are US; `en-GB`, `en-419` and `en-x-us` are not.

Alaska does not guess. Quotes and apostrophes are on for `en`, `ru` and `ko`; the short-word no-break space, the numeric range and the em dash are on for `en` and `ru` only. Any other language, including `ja`, and a missing language, leaves the language-dependent rules off. The numeric range is language-dependent because `ja` and `ko` conventionally write ranges with `{U+301C}` or `~`, not an en dash. The em dash is language-dependent because `ja` and `ko` have their own dash conventions (Japanese typesetting commonly uses a doubled horizontal bar, `{U+2015}{U+2015}`), which this rule does not apply. Every other rule is language-independent. `placeHyphen` is script-gated rather than language-gated: it needs a Latin or Cyrillic letter on both sides, so in `ja` and `ko` text only Latin fragments (`Wi-Fi`, `K-pop`) are touched. `ko` has quotes only: `'` and `"` are treated alike there too, so `'좋아'` at the outer level becomes a double quote.

## Per-element rule overrides

Any rule can be switched per element with a `data-*` attribute, in kebab-case, on or inside an `.alaska` element. The setting applies to the element and inherits to its descendants:

```html
<div class="alaska" data-place-emdash="false">a - b stays as written</div>
<p data-place-number-nbsp-word="false">5 m stays as written</p>
```

Only the exact values `"true"` and `"false"` are meaningful. Use them. Other values are kept as strings: any non-empty string (for example `"0"`) turns the rule on, and an empty value (bare `data-place-emdash`) turns it off. Attributes that are not rule names are ignored.

## Math

Prose rules never guess algebra, so `placeArithmeticalSymbols` is off by default and `3 + 4`, `3 - 4` and `5 - 3` are left as written. Mark a math zone with `data-math="true"` on or inside an `.alaska` element. It inherits to descendants, and `data-math="false"` on a descendant restores the prose defaults for that subtree:

```html
<p class="alaska" data-math="true">x - 5</p> <!-- x {U+2212} 5 -->
```

The zone applies `mathRules` over the current rules: `placeArithmeticalSymbols` on; `placeEmdash`, `placeNumericRange`, `placeHyphen` and `placeNbsp` off. Order of precedence: inherited rules, then the `data-math` overlay, then explicit `data-place-*` attributes on the same element. Any `data-math` value other than `"true"` and `"false"` is ignored. In the core, pass `{ ...commonRules, ...mathRules }`.

A zone is for formulas in plain text. An operator changes its glyph only and never touches whitespace: spaces, line breaks and no-break spaces stay as written, and the short-word no-break space is off. The number-unit glue of `placeNumberNbspWord` stays on, because a unit is not an operator: `x = 3 m` and `x = 50 %` still get their single regular space converted. A unary minus is the glued form (see `placeMinusSign`) and also precedes a word or follows `= + * / < >` (`x=-y`). Words are operands, so a spaced hyphen between two words becomes a minus (`Therefore - note`), and an operator in an inline element of its own is not seen (see [Scope](#scope)).

In a zone, `\star` and `\diamond` give U+22C6 and U+22C4 instead of U+2606 and U+25C7. This follows `placeArithmeticalSymbols`, so it also applies with `data-place-arithmetical-symbols="true"` and no `data-math`; `placeShapes` still gates it. A shortcode cannot give U+2606 or U+25C7 in a zone: put `data-math="false"` on that element, or write the character itself.

## Scope

Alaska formats prose and does not guess. It leaves ambiguous text as written, so a missed edit is expected and a wrong edit is a bug. The shapes below are the known exceptions: they are decided by shape, not by meaning. Each one is pinned by a test, so changing it is a deliberate edit.

- **Prose only.** Code, paths and identifiers belong in `<code>` or `alaska-skip`, or under a `data-*` override. A backslash followed by ASCII letters is a shortcode, so `C:\pi` gives `C:{U+03C0}`; `<-` is an arrow, so `x <- 5` and `x<-y` give `{U+2190}`.
- **A tight number, hyphen, number is a range.** This is the one accepted guess. `555-1234`, `2024-01`, `1.2-3`, `10-5` and `example.com/2024-05` cannot be told from a range and get an en dash. A chain (`2024-01-15`) and a number after a word (`x86-64`) are left alone.
- **Initials and short words match by shape and spelling.** `Plan B. Then` gives `B.{U+00A0}Then`. `Vitamin A and C` gives `A{U+00A0}and{U+00A0}C` and `Q&A session` gives `Q&A{U+00A0}session`. A spaced `%` after a number is a percent sign even when it is modulo (`10 % y`).
- **Quotes are classified by shape.** Known ambiguities: a possessive plural inside `'...'` (`'The dogs' owners left'` closes early; the glyphs are right, the nesting depth after it is not), an inch mark inside `"..."` (`"She is 5'10" tall"`), an elision outside `em til tis twas cause bout round` or a capitalised one (`'Twas`, `'99`), which is read as an opener, and a lowercase quote that starts with one of those words, which is read as an elision (`'round the world,' he said`).
- **Lookahead rules decide within one piece.** Text split by inline elements reaches the core in pieces (see [Carry](#carry)). Wrong or missed edits at such a boundary (`1-2<b>-3</b>`, `my-site<b>.example.com</b>`, `it'<b>s</b>`, `5-<b>star</b>`) are accepted as one carve-out and not listed one by one. They are rare, and a fix needs an end-of-text flag in the API.
- **The CLI and the browser see character references differently.** The CLI passes a reference through and ends the text run at it, so it counts as a word: `Tom &amp; Jerry` is not bound and `-&gt;` is not an arrow. The browser reads decoded text, so it binds the `&` and forms the arrow. Decoding and re-encoding would rewrite the author's references, so the two are not unified. In practice the `&` binding rarely fires in CLI output, because HTML spells it `&amp;`.
- **Math zone.** Words are operands, so `Therefore - note` gives `Therefore {U+2212} note`. A `%` is not an operand, and a number starts with a digit, which is why `-.5`, `-$.5` and a bare `-\euro` are left alone.
