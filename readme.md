# Alaska is a text formatter for web prose.

It applies typographic conventions to text: quotes, no-break spaces, dashes, arrows, symbols, and more.

The formatting engine `src/core.js` can be used in:

- [browser](#browser) via `browser/alaska.js` to format a page in the client, including text added later;
- [source](#vendored-core) via `src/core.js` to format strings in code, at render time;
- [CLI](#cli) via `cli/cli.js` to format static HTML files in place at build time.

## Notation

Formatted output contains invisible and lookalike characters. Examples write any non-ASCII character as `{U+XXXX}`, meaning one character with that codepoint. It is documentation notation, not input syntax.

| Notation   | Name                                            |
| ---------- | ----------------------------------------------- |
| `{U+00A0}` | NO-BREAK SPACE                                  |
| `{U+202F}` | NARROW NO-BREAK SPACE                           |
| `{U+200A}` | HAIR SPACE                                      |
| `{U+2060}` | WORD JOINER (zero width, prevents a line break) |
| `{U+FE0E}` | VARIATION SELECTOR-15 (text presentation)       |

## Browser

Link `browser/alaska.js` in the head of a page:

```html
<html lang="en">
  <head>
    <script src="browser/alaska.js"></script>
  </head>
  <body class="alaska">
    <p lang="ru">Alaska applies Russian conventions to this element.</p>
    <p class="alaska-skip">Alaska does not format this element.</p>
    <div class="alaska-observe">Alaska formats nodes added to this element later.</div>
  </body>
</html>
```

`browser/alaska.js` is generated by `deno task build` from `src/core.js` and `src/dom.js`. It exposes no global and no JS API. Configuration is only through classes, `lang` and `data-*` attributes.

| Class            | Effect                                                                                                                                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `alaska`         | Text inside the element is formatted. Formatting is idempotent: formatting already-formatted text returns it unchanged. `test/fuzz.js` checks this on random strings under prose and math rules, in `en`, `ru` and no language. It is tested, not proven. Format at render time regardless. |
| `alaska-skip`    | The element and its subtree are not formatted.                                                                                                                                                                                                                                              |
| `alaska-observe` | A `MutationObserver` formats nodes added inside this element after load. It must be on or inside an `.alaska` element.                                                                                                                                                                      |

Always skipped inside `.alaska`: `code`, `pre`, `samp`, `kbd`, `script`, `style`. An `.alaska` element inside a skipped element (those, or `.alaska-skip`) is not a root and is not formatted.

Only the outermost `.alaska` is a root. A `.alaska` inside another `.alaska` is not formatted separately; it is traversed like any other element, and its own `lang` and `data-*` attributes apply to its subtree.

Observer scope: it watches `childList` on the subtree. Added or replaced nodes are formatted, including via `innerHTML` and `el.textContent = "..."`. In-place edits of an existing text node (`textNode.data`, `nodeValue`) are not observed, so text rewritten that way by a framework or script stays unformatted. An added node uses the `lang` and `data-*` attributes of its ancestors up to the outermost `.alaska`.

Inline elements do not break formatting within a block: `"Hello <b>x</b>"` pairs its quotes, and a minus sign or line-start dash looks at the text before the element. Block-level elements (`blockTags` in `src/core.js`) and `<br>` start a new line of context; `code`, `kbd`, `samp` and inline `.alaska-skip` elements count as a word. The observer sees only the added nodes, so it pairs quotes only in nodes added at the start of a block or in added block elements, and it does not format a minus sign or line-start dash at the start of any other added node.

## Vendored core

Use `src/core.js` into your code:

```js
import { commonRules, formatString, mathRules } from "./vendor/alaska/core.js";

formatString("5 meters", commonRules, "en"); // 5{U+00A0}meters
formatString("50%", { ...commonRules, placePercentSign: false }, "en"); // 50%
```

### `formatString(text, rules, lang, carry)`

| Param   | Type     | Notes                                                                 |
| ------- | -------- | --------------------------------------------------------------------- |
| `text`  | `string` | Input longer than 2,000,000 characters is returned unchanged.         |
| `rules` | `object` | Required. `undefined` throws a `TypeError`.                           |
| `lang`  | `string` | Language tag. See [Language](#language). May be `undefined`.          |
| `carry` | `object` | Optional. Shared across the pieces of one block. See [Carry](#carry). |

Returns the formatted string.

`commonRules` maps every rule name to its prose default: `true` for every rule except `placeArithmeticalSymbols`. `mathRules` is an overlay for [math zones](#math): `formatString("x - 5", { ...commonRules, ...mathRules }, "en")` gives `x{U+200A}{U+2212}{U+200A}5`. A key missing from `rules` counts as off, so a partial object enables only the rules it lists:

```js
formatString("5 meters 50%", { placePercentSign: true }, "en"); // 5 meters %{U+202F}50
```

To disable one rule, spread `commonRules` and set it to `false`. To enable a subset, pass only those keys.

Call it on whole text blocks (a paragraph, a heading, a cell), not on fragments. Without a `carry`, quote pairing and neighbor-dependent rules see only the string you pass. See [Carry](#carry) and [bugs.md](bugs.md).

### Carry

Text split by inline elements (`"Hello <b>x</b>"`) reaches `formatString` in pieces. Pass the same `carry` object, a plain `{}`, to every piece of one block in document order, and quote pairing, the minus sign and the line-start dash read across the piece boundary. The object is opaque: only the core reads or writes it.

```js
import { commonRules, formatString, resetCarry } from "./vendor/alaska/core.js";

const carry = {};
formatString('"Hello', commonRules, "en", carry); // {U+2018}{U+2060}Hello
formatString(" x", commonRules, "en", carry); // {U+0020}x
formatString('"', commonRules, "en", carry); // {U+2060}{U+2019}
resetCarry(carry); // at every block boundary
```

Call `resetCarry` at the start and end of each block-level element. `blockTags` is the set of lowercase tag names the browser and CLI treat as blocks. Without `carry`, every call stands alone. Lookahead rules still see only the current piece (`5 <b>meters</b>`, `it'<b>s</b>`); see [bugs.md](bugs.md).

## CLI

Rewrites HTML files in place. Only text inside `.alaska` elements is changed. Files are written only if the output differs.

```sh
deno run -R -W cli/cli.js page.html docs/*.html --exclude 'docs/drafts/*'
```

- Arguments other than `--exclude` are file paths. The shell expands globs before the CLI sees them.
- `--exclude <pattern>` is repeatable. It is matched against each path exactly as given, so `./a.html` and `a.html` are different strings. `*` matches any characters including `/`, `?` matches one character, `[abc]` and `[!abc]` are character classes. Patterns are anchored to the whole path.
- Exit code is 1 if no files are given or any file fails.
- `lang`, `data-*` rule attributes, `alaska-skip`, and the skip elements behave as in the browser. `alaska-observe` has no effect.
- The parser is a streaming rewriter, not a full HTML parser. It handles void elements, optional end tags, `script`/`style` contents, and self-closing tags in `svg` and `math`. Character references (`&amp;`, `&nbsp;`) are passed through untouched and split the surrounding text into separate `formatString` calls that share one [carry](#carry): a reference that decodes to whitespace (`&nbsp;`, `&#32;`) counts as whitespace, any other as a word.
- The rewrite is in place, so the source files become formatted. Running it again changes nothing (formatting is idempotent, see [Output contract](#output-contract)).

## Rules

There are 23 rules. All are on by default except `placeArithmeticalSymbols`, which is for [math zones](#math). Raw input is ASCII unless written in the notation; output uses the notation above.

| Rule                           | Raw            | Formatted                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------ | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `placeNumberNbspWord`          | `5 meters`     | `5{U+00A0}meters`. Only a single regular space between a number and the next word. Left alone: a newline (including in hard-wrapped HTML source), repeated spaces, other space characters (`{U+202F}`, `{U+3000}`) and a number with trailing punctuation (`in 2024. We`, `5, then`)                                                                                                               |
| `placeThreeStops`              | `wait...`      | `wait{U+2060}.{U+2060}.{U+2060}.{U+2060}` (also applies to U+2026)                                                                                                                                                                                                                                                                                                                                 |
| `placeFractions`               | `3/4`          | `3{U+2044}4` (U+2044 FRACTION SLASH). Only tight `d/d` with no neighboring `/`: `12/05/2024` and `example.com/2024/05` are left alone                                                                                                                                                                                                                                                              |
| `placeArithmeticalSymbols`     | `x - 5`        | `x{U+200A}{U+2212}{U+200A}5` (U+2212 MINUS SIGN). Math zones only, off in prose (see [Math](#math)). Spaced `+ - = * /` between numbers, words, `(` and `)` get hair spaces; `*` becomes U+22C5 and `/` becomes U+2215                                                                                                                                                                             |
| `placeMinusSign`               | `-5`           | `{U+2212}5`. Only directly before a number or currency (`-$20` and `-20USD` both give `{U+2212}${U+202F}20`), and only at the start or after whitespace, `(` or `[`. `COVID-19`, `H-1B`, `a-5` and (in prose) `-(5)` are untouched. In a math zone `-(5)` gives `{U+2212}(5)`                                                                                                                      |
| `placeEmdash`                  | `a -- b`       | `a{U+00A0}{U+2014} b` (U+2014 EM DASH). Also fires on a spaced `-` with a word on the left and a word, number or currency on the right (`a - b`, `value - 5`), and at line start (`- item`, `- 5`). Untouched: `--` next to another dash (`----`), and a spaced `-` after a number or next to punctuation (`5 - 3`, `x - - y`, `a - , b`)                                                          |
| `placeNumericRange`            | `10-20`        | `10{U+2060}{U+2013}{U+2060}20` (U+2013 EN DASH). Tight, with a number on both sides. Open-ended `2024-` also applies, at the end of the text or before a space (`from 2024- on`; `5- 3` is read the same way). `5-star` and `3-D` are untouched                                                                                                                                                    |
| `placeCopyright`               | `(c)`          | `{U+00A9}`. Also `(p)` gives U+2117, `(tm)` gives U+2122, `(r)` gives U+00AE                                                                                                                                                                                                                                                                                                                       |
| `placeNumeroSign`              | `No. 4`        | `{U+2116}{U+202F}4`. Without the space, `No.4` gives `{U+2116}{U+202F}{U+2060}4`. Case-insensitive                                                                                                                                                                                                                                                                                                 |
| `placeMathematicalSymbols`     | `\pm`          | `{U+00B1}`. Also `\dia` gives U+2300                                                                                                                                                                                                                                                                                                                                                               |
| `placeGreekSymbols`            | `\alpha`       | `{U+03B1}`. LaTeX names, case-sensitive: `\Delta` gives U+0394, `\delta` gives U+03B4. Variants: `\varepsilon` gives U+03F5, `\vartheta`, `\varkappa`, `\varpi`, `\varrho`, `\varsigma`, `\varphi`. `\epsilon` and `\phi` give the letters U+03B5 and U+03C6. Names LaTeX lacks (`\Alpha`, `\omicron`) are left as written                                                                         |
| `placeTypographyOrnamentation` | `\dinkus`      | `{U+2217}{U+2060}{U+2217}{U+2060}{U+2217}`. Also `\asterism` gives U+2042, `\S` gives U+00A7, `\P` gives U+00B6, `\dag` gives U+2020, `\ddag` gives U+2021, `\bullet` gives U+2022                                                                                                                                                                                                                 |
| `placeEmoticons`               | `\shrug`       | `{U+00AF}{U+2060}\{U+2060}_{U+2060}({U+2060}{U+30C4}{U+2060}){U+2060}_{U+2060}/{U+2060}{U+00AF}`                                                                                                                                                                                                                                                                                                   |
| `placeCurrencySign`            | `USD 100`      | `${U+202F}100`. Symbol always moves before the number: `100 USD`, `$100` give the same. Codes: usd, eur, gbp, jpy, cny (gives `CN{U+00A5}`), rub, kzt, case-insensitive. Symbols: `$`, `{U+20AC}`, `{U+00A5}`, `{U+00A3}`, `{U+20BD}`, `{U+20B8}`                                                                                                                                                  |
| `placePercentSign`             | `50%`          | `%{U+202F}50`. The sign moves before the number on purpose: the sign carries more meaning than the number. A leading `%` before a number gets the narrow space too (`%50` gives `%{U+202F}50`). `1%20` (percent between digits) is untouched                                                                                                                                                       |
| `placeNbsp`                    | `it is a test` | `it is a{U+00A0}test`. The space after a short word becomes U+00A0; also when the word is followed by a comma. Word lists exist for `en` and `ru` only                                                                                                                                                                                                                                             |
| `placeHyphen`                  | `well-known`   | `well{U+2060}-{U+2060}known`. Also after a temperature: `20oC-warm`                                                                                                                                                                                                                                                                                                                                |
| `placeTemperatureSign`         | `100oC`        | `100{U+202F}{U+00B0}C`. Also `oF`. ASCII lowercase `o`. The number must end in a digit (`5.oC` is untouched). The unit may be followed directly by a Han, Kana or Hangul letter (`20oC{U+3067}` gives `20{U+202F}{U+00B0}C{U+3067}`), not by a Latin or Cyrillic letter (`20oCa`). The `C` is not read as an initial (`20oC. Then`)                                                                |
| `placeMultiplicationSign`      | `3 x 4`        | `3{U+202F}{U+00D7}{U+202F}4`. An `x`, `X` or typed `{U+00D7}` between two numbers. A single regular or no-break space on each side becomes `{U+202F}` (`{U+200A}` in a math zone). Other whitespace and missing spaces are left as written, so `1920x1080` gives `1920{U+00D7}1080`. Declined: `0x10`, `a x 4`, `3 x b`, `3. x 4` and Cyrillic `{U+0445}`                                          |
| `placeTypographicQuotes`       | `"hello"`      | `{U+2018}{U+2060}hello{U+2060}{U+2019}` for `en`. Only for `en` and `ru`: with any other language, or none, quotes and apostrophes are left as written (see [Language](#language)). `"` and `'` are treated alike; nesting alternates by depth. An apostrophe between letters becomes `{U+2019}` (`it's` gives `it{U+2019}s`); at word end it gets a joiner (`dogs'` gives `dogs{U+2060}{U+2019}`) |
| `formatInitials`               | `J. Smith`     | `J.{U+00A0}Smith`. An initial is one capital letter and a period. Whitespace between initials becomes `{U+202F}` (`J. K. Smith` gives `J.{U+202F}K.{U+00A0}Smith`); before a capitalized word it becomes `{U+00A0}`. A lone `I` is skipped unless chained (`I. M. Pei`). Spaces are never inserted: `J.K.Rowling` is left alone. Not handled: `Mr. Smith`, `JK Rowling`                            |
| `placeArrows`                  | `item -> next` | `item {U+2192} next`. `<-` gives U+2190 and `<->` gives U+2194. Wins over `placeNumericRange`: `10->20` gives `10{U+2192}20`. Shortcodes: `\arrn` gives U+2191, `\arre` gives U+2192, `\arrw` gives U+2190, `\arrlr` gives U+2194, `\arrud` gives U+2195, plus `\arrs \arrne \arrse \arrsw \arrnw`                                                                                                 |
| `placeShapes`                  | `\square`      | `{U+25A1}`. Filled shapes take a `black` prefix: `\blacksquare` gives U+25A0. Plain names: `\square \circle \triangle \triangledown \triangleleft \triangleright \diamond \lozenge \star \heart \hexagon \pentagon \spade \club`, plus `\doublecircle` (U+25CE) and `\tainome` (U+25C9)                                                                                                            |

Shortcodes (`\pm`, `\alpha`, `\dinkus`, `\shrug`, `\arrn`, `\square`) are gated by their own category rule. A shortcode is a backslash followed by ASCII letters of either case, and names are case-sensitive. Unknown shortcodes are left as written. The shortcode sets are not final and may change; the tables in `src/core.js` (`mathShortcodes`, `greekShortcodes`, `ornamentShortcodes`, `emoticonShortcodes`, `arrowShortcodes`, `shapeShortcodes`) are the source of truth. Shape names follow LaTeX where one exists, except `\star` and `\diamond`, which give U+2606 and U+25C7 (LaTeX's are U+22C6 and U+22C4). `\blacktriangleleft`, `\blacktriangleright`, `\blackheart`, `\blackspade` and `\blackclub` end with `{U+FE0E}` so platforms draw them as text, not colour emoji.

## Language

Language comes from the `lang` attribute of the nearest element (browser and CLI) or the `lang` argument (core). It inherits down the tree. In the browser, an empty `lang=""` inherits; in the CLI, an explicit `lang=""` resets to no language.

Only the primary subtag is read: the text before the first `-`, lowercased. `en`, `EN` and `en-US` all mean `en`. Tags with an underscore (`en_US`) and language names (`english`) are not recognized.

Alaska does not guess. Any language other than `en` and `ru`, and a missing language, leaves the language-dependent rules off. Every other rule is language-independent.

| Primary subtag         | Quotes                                                                                   | Apostrophe between letters | Short-word nbsp |
| ---------------------- | ---------------------------------------------------------------------------------------- | -------------------------- | --------------- |
| `en`                   | outer `{U+2018}{U+2060}...{U+2060}{U+2019}`, inner `{U+201C}{U+2060}...{U+2060}{U+201D}` | `{U+2019}`                 | English list    |
| `ru`                   | outer `{U+00AB}{U+2060}...{U+2060}{U+00BB}`, inner `{U+201E}{U+2060}...{U+2060}{U+201C}` | `{U+2019}`                 | Russian list    |
| anything else, or none | unchanged                                                                                | unchanged                  | none            |

## Per-element rule overrides

Any rule can be switched per element with a `data-*` attribute, in kebab-case, on or inside an `.alaska` element. The setting applies to the element and inherits to its descendants:

```html
<div class="alaska" data-place-emdash="false">a - b stays as written</div>
<p data-place-percent-sign="false">50% stays as written</p>
```

Only the exact values `"true"` and `"false"` are meaningful. Use them. Other values are kept as strings: any non-empty string (for example `"0"`) turns the rule on, and an empty value (bare `data-place-emdash`) turns it off. Attributes that are not rule names are ignored.

## Math

Prose rules never guess algebra, so `placeArithmeticalSymbols` is off by default and `3 + 4`, `3 - 4` and `5 - 3` are left as written. Mark a math zone with `data-math="true"` on or inside an `.alaska` element. It inherits to descendants, and `data-math="false"` on a descendant restores the prose defaults for that subtree:

```html
<p class="alaska" data-math="true">x - 5</p> <!-- x{U+200A}{U+2212}{U+200A}5 -->
```

The zone applies `mathRules` over the current rules: `placeArithmeticalSymbols` on; `placeEmdash`, `placeNumericRange` and `placeHyphen` off. Order of precedence: inherited rules, then the `data-math` overlay, then explicit `data-place-*` attributes on the same element. Any `data-math` value other than `"true"` and `"false"` is ignored. In the core, pass `{ ...commonRules, ...mathRules }`.

In a zone, a short-word variable keeps its no-break space on the left: `a + b` gives `a{U+00A0}+{U+200A}b`.
